## Context

См. `proposal.md` — Why / What Changes. Из `Schemas/KnGitGuiMessageBox/KnGitGuiMessageBox.js`, применительно к трём кнопкам в рамках этого изменения (актуально на момент реализации):

- `renderPullButton()` создаёт `BPMSoft.Button` со `style: "transparent"`, `caption: "Получить изменения с сервера"`, без `imageConfig` (иконка убрана).
- `renderDownloadChangesToFSButton()` создаёт кнопку со `style: "transparent"`, `caption: "Выгрузить в файловую систему"`, без `imageConfig`.
- `renderRefreshButton()` создаёт кнопку со `style: "transparent"`, `caption: "Обновить реестр"`, без `imageConfig` (как и было изначально).
- Все три рендерятся в контейнеры `KnGitGuiMessageBox-reload-button`, `KnGitGuiMessageBox-pull-button`, `KnGitGuiMessageBox-refresh-button`, которые `getTpl()` располагает рядом в одной строке `header-with-button`, вместе с текстом "Незафиксированные изменения".
- Остальные кнопки Git GUI (кнопка в шапке, "Закрыть", "Помощь", "Коммит", "Push") не входят в рамки этого изменения и здесь не рассматриваются.

## Goals / Non-Goals

**Goals:**
- Pull и "выгрузить в файловую систему" показывают только текстовую подпись, без иконки — как и "Обновить реестр".
- Все три кнопки используют единый видимый стиль (рамка/заливка), реализованный собственным CSS.
- Эти три кнопки расположены компактно в существующей строке `header-with-button`, без лишних промежутков, и умещаются в ней.

**Non-Goals:**
- Кнопка в шапке, "Закрыть", "Помощь", "Коммит" и "Push" не меняются в этом изменении — ни подпись/иконка, ни стиль, ни расположение.
- Действия кнопок (обработка событий, вызовы сервисов, тексты подтверждений) не меняются — меняется только представление и раскладка этих трёх кнопок.
- Иконки для этих трёх кнопок не используются вообще — ни существующие (`imageConfig` убран), ни новые.
- Регистрация строк локализации в дизайнере BPMSoft — вне рамок реализации кода; это ручной шаг, который выполняется отдельно.

## Decisions

- **Убрать иконки у Pull и Download полностью, оставить только `caption`.** Изначально рассматривался комбинированный вариант "иконка + подпись в одну строку" (см. историю итераций ниже), но по прямому запросу иконки решили убрать совсем — это также снимает все сложности с обрезанием иконки платформенным стилем и с ещё не зарегистрированными ресурсами изображений.
- **`style` остаётся `"transparent"` у всех трёх кнопок; видимая рамка/заливка — через собственный CSS.** Пробовали платформенный `ButtonEnums.style.DEFAULT` — он дал слишком крупную кнопку и (пока были иконки) обрезал их внутри своего фиксированного бокса.
- **Рамка/заливка реализована на контейнерах `<div>` из `getTpl()` (`#KnGitGuiMessageBox-refresh-button` / `-reload-button` / `-pull-button`), а не на внутреннем `-wrapperEl` кнопки `BPMSoft.Button`.** Первая попытка стилизовать через `#GitGuiRefreshButton-wrapperEl` и аналогичные ID дала рамку не для всех трёх кнопок одинаково (у "Обновить реестр" рамка не отрисовывалась) — вероятно, внутренняя разметка `BPMSoft.Button` не идентична между кнопками с иконкой и без неё, либо перекрывается более специфичными платформенными правилами. Контейнеры `getTpl()` — это разметка, которую мы полностью контролируем и гарантированно можем стилизовать одинаково для всех трёх кнопок.
- **Не трогать позиционирование/раскладку остальных элементов диалога (Close/Help/Commit/Push).** Строка `header-with-button` донастраивается только под сами три кнопки (отступы/`gap`), без переноса в неё Close/Help — это осознанно оставлено за рамками текущего изменения.
- **Не создавать/не редактировать ресурсы локализации как часть реализации.** Подписи заданы в коде как обычные значения `caption` (текстовый литерал, по тому же паттерну, что уже использован для Commit/Push/Refresh); фактическую регистрацию строки как локализуемого ресурса выполняет пользователь вручную через дизайнер BPMSoft — отдельно от изменений в `.js`/`.less`.

## Risks / Trade-offs

- [Pull и Download стали шире после добавления подписи и могут не поместиться в строке `header-with-button` рядом с текстом "Незафиксированные изменения"] → Проверить визуально после реализации; при необходимости перенести/сократить текст или уменьшить отступы, не расширяя диалог.
- [Три кнопки визуально отличаются от остальных кнопок диалога (Close/Help/Commit/Push остаются прозрачными без рамки), что может выглядеть непоследовательно до тех пор, пока остальные кнопки не будут приведены к тому же виду] → Осознанный компромисс по явному запросу ограничить область изменения; распространение на остальные кнопки — материал для отдельного последующего изменения.
- [Собственный CSS через `var(--field-underline)` может визуально разойтись с фирменным цветом/радиусом платформы] → Приемлемо: `var(--field-underline)` уже используется в этом файле (например, для рамки поля сообщения коммита), значит переменная точно доступна в теме; при необходимости цвет/радиус можно скорректировать без изменения структуры.

## Migration Plan

Прямое изменение кода, без миграции данных. Выкатывается как обычное развёртывание пакета; откат — возврат изменённых `.js`/`.less` файлов, если новый вид трёх кнопок окажется хуже на практике.

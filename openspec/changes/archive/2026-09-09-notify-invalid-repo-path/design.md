## Context

`prepareCollection` в `KnGitGuiMixin.js` вызывает `ServiceHelper.callService("KnCommiterService", "GetRepoStatusWithSchemas", ...)`. При ошибке (`GitCliException` внутри `KnCommiterService.GetRepoStatusWithSchemas`) ответ содержит `Status` с текстом ошибки, а `Log`/`Schemas` равны `null`. Текущий код входит в обработку результата только по условию `response.GetRepoStatusWithSchemasResult.Log`, поэтому при ошибке колбэк `showModalBox` не вызывается и внешний `callback` теряется — диалог не открывается без всякой обратной связи.

## Goals / Non-Goals

**Goals:**
- При отсутствии `Log` в ответе показывать пользователю единое сообщение об ошибке через `BPMSoft.showErrorMessage`.

**Non-Goals:**
- Различать причину ошибки (пустой путь / несуществующий каталог / не git-репозиторий).
- Валидация пути на этапе сохранения системной настройки.
- Вынесение текста сообщения в локализуемые ресурсы.

## Decisions

Добавить в `prepareCollection` ветку `else` (или проверку в начале колбэка) на случай отсутствия `Log`: вызвать `BPMSoft.showErrorMessage("<универсальный текст>")` и не продолжать открытие диалога. Текст хардкодится строкой в JS, как остальные сообщения в этом файле (`applyCommit`, `pushChanges`, `pullChanges`) — по образцу существующего кода, без новой инфраструктуры.

Проверка делается по факту отсутствия `Log`, а не по содержимому `Status`, — так поведение остаётся единым независимо от точного текста git-ошибки в `Status`.

## Risks / Trade-offs

Единое сообщение не укажет точную причину (пустой путь vs. невалидный репозиторий) → пользователь может не сразу понять, что именно исправить; смягчается тем, что сообщение прямо указывает проверить настройку пути до репозитория.

## Context

См. `proposal.md`. Тур реализован полностью в `onHelpButtonClick` (`Schemas/KnGitGuiMessageBox/KnGitGuiMessageBox.js`): локальный массив `steps`, DOM-оверлей `.tour-layer` создаётся через `modal.appendChild(layer)` без проверки, не создан ли он уже. Сейчас в массиве `steps` для трёх кнопок над реестром: шаг `download-changes-button` стоит на позиции 3 (после "last"/"unstaged"), шаг `pull-button` — последним (после push-кнопок), шага для `refresh-button` нет вовсе.

## Goals / Non-Goals

**Goals:**
- Три шага тура для кнопок над реестром (`refresh-button`, `download-changes-button`, `pull-button`) идут подряд, в порядке "Обновить реестр" → "выгрузить в ФС" → Pull, в той точке массива `steps`, где сейчас стоит `download-changes-button` (шаг `pull-button` переносится туда же из конца массива).
- Повторное нажатие "Помощь" при уже активном туре — no-op.
- Закрытие диалога во время активного тура удаляет `.tour-layer`.

**Non-Goals:**
- CSS/`pointer-events` оверлея не меняются — блокировка повторного нажатия делается только на уровне JS.
- Поведение "клик по подложке вне попапа переключает шаг" не чинится — вне рамок этого изменения.
- Поведение при `onAfterReRender` (пересборка диалога без закрытия) не рассматривается — тур в этом сценарии не наблюдался как проблема.

## Decisions

- **Guard и очистка через DOM-запрос, без нового поля состояния.** И `onHelpButtonClick`, и обработчик закрытия проверяют `modal.querySelector(".tour-layer")` вместо кэширования ссылки на `this`. Это исключает рассинхронизацию (например, если `layer` был удалён в обход `end()`) — DOM остаётся единственным источником истины.
- **`onHelpButtonClick` в начале: если `.tour-layer` уже есть — `return`.** Тур не перезапускается, не пересоздаётся.
- **Закрытие диалога удаляет `.tour-layer` перед скрытием.** Логично разместить в `onCloseMessageBoxButtonClick` (перед вызовом `this.hide()`), т.к. это единственный обработчик пользовательского закрытия; `setVisible`/`hide` не трогаются.
- **Текст нового шага `refresh-button`** пишется в стиле соседних шагов (короткое описание действия кнопки), финальная формулировка — на этапе реализации.

## Risks / Trade-offs

- [DOM-запрос `.tour-layer` при каждом клике "Помощь"] → Дешёвая операция (один `querySelector` в пределах модалки), не требует отдельного бенчмарка.
